## 实现

- 前端为每次运行的独立辅导会话生成conversationId，每次新问题生成turnId。切步骤和收起浮窗保留会话；输入失效或新建运行更换会话。重试使用完整原请求快照，含原运行、步骤、级别与两个ID。
- 服务端按socket来源、runId、conversationId隔离内存记录；只记录成功且有知识依据的完整问答，最多10轮，问题/回答/话题文本总长度最多8000个UTF-16字符，超限移除最早完整轮。保留期为1小时无活动；最多200个会话，容量不足淘汰最久未活动且未执行的会话，全部执行中时返回429。重启后清空，不写入磁盘。
- 同一会话串行处理；同时提问返回409 CONVERSATION_BUSY。同turnId且相同问题/步骤/级别可重放保留窗口内的成功结果，避免网络重试重复调用付费模型；重复ID改写请求返回400。失败、无关问题和资料不足不写入学习历史。
- 浏览器不上传历史问答、助手角色或变量。后端仅使用自己保存的历史；本轮及历史步骤的权威变量都从服务端run读取。旧对话在prompt中明确标为参考数据，不是指令或权威状态。
- 省略主语的追问结合上一个成功话题检索；明确新主题和明确当前步骤的问题独立检索。未命中不凭旧话题硬凑引用，不调用真实模型。
- 提示词改为耐心、直白的同学助教：先回答具体困惑，简单问题两三句话，需要时再展开计算或例子；不固定列“首先其次”，不重复夸奖，不强制以反问结尾，不懂时换解释方式。保留三级深度、真实状态优先及不编造来源。
- 移除按“答案是/结果就是”一律拦截的规则，允许解释已显示状态；保留空输出/长度检查和有限的闭区间误解检查。这些规则不能保证模型回答全部正确。
- 回答正文不再自动附整张知识卡；sourceRefs仍返回并由界面展示。算法、评分、布局、模型配置和用量预算逻辑保持原接口行为。

## 使用

重新启动生产服务（npm.cmd start）后刷新页面，在同一运行中先问“为什么必须有序”，再问“能再讲详细一点吗”或“换个说法”。新建运行后旧记录仍可回顾，但不作为新会话上下文。模型关闭时仍明确显示Mock/未配置；连续追问功能不将Mock变成真实模型。
