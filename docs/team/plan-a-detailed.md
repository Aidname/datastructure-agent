## 1. 本次交付边界

本次交付完整的第一次作业材料和一个二分查找运行样例。正式版的全内容覆盖、八类重点动画作为需求规划，不在这次全部实现。

样例必须串起：输入数组与目标 → 生成实际执行轨迹 → 动画/代码/变量同步 → 暂停后向 Agent 提问 → 做过程题 → 保存本机错题与进度。

数据约定：升序安全整数数组，下标从0开始，重复值允许返回任一实际匹配位置；采用闭区间实现。执行状态由程序产生，不由模型生成。业务接口和轨迹字段按 docs/architecture 的共同契约；修改必须同步消费者。

- 与04确定闭区间实现、事件名、变量字段、稳定代码行标识；让02、03、05、07确认同一份契约。
- 统一目录、启动方式、依赖变更和分支命名；协调公共文件，不让所有人修改同一个入口。
- 维护PR和阻塞记录，17/19日组织集成；出现接不上的模块，记录具体字段或调用问题并分给相应负责人。
- 21日全流程验收，22日核对功能清单、资料清单、已知问题、版本和启动说明并冻结范围，组织23日至24日答辩前的修复、复测与演练。

### 主责路径

docs/team/、docs/architecture/、shared/schemas/、scripts/、根配置。前端入口由02实际维护，后端入口由04实际维护，01协调审查。

### 验收条件

每人身份、负责路径和日期明确；接口能由各模块使用；从干净副本按README启动成功；所有本次必须交付项都有负责人、实际状态和证据。

## 4. 成员 02：页面与输入、代码变量

### 具体实现

1. 建立电脑端工作台：输入控制区、动画区、代码变量区、Agent区、练习区，保留独立挂载位置。
2. 数组/目标输入、示例填入、开始按钮；格式错误和无序输入显示具体提示，不能偷偷排序。
3. 调用04创建运行接口；按钮有加载状态，失败可重新提交。
4. 展示04提供的C/C++代码，通过lineId高亮；变量显示left/right/mid，null显示“未计算”，不能显示成0。
5. 接收03当前步骤变化，让代码和变量同步；把runId/stepIndex提供给05/07。
6. 输入变化创建新run，并取消旧播放、区分旧问答与新任务；不在前端另写一个二分算法。

### 主责路径

frontend/index.html、frontend/src/app.js、frontend/src/styles/、frontend/src/features/workbench/、frontend/src/services/。

### 依赖与验收

依赖04的run/step/sourceLines，03的步骤通知。先用清楚标明mock的样例布局，17日接真数据。验收：有效输入生成任务；非法输入提示；每步代码和变量一致；快速重新提交不混入旧状态。

## 5. 成员 03：动画与播放

### 具体实现

1. 依步骤array绘制格子和下标；标记left/right/mid、搜索区间、匹配位置与结束状态。
2. 实现开始/暂停、下一步、上一步、速度调整和重置。维护播放指针，不重算算法。
3. 发布当前步骤给02、05、07；停止后留在可提问的实际步骤。
4. 正确呈现mid=null、空数组和空区间；回看历史快照，不能把已经更新的数据套到旧步骤。
5. 清除旧计时器，处理播放结束、快速切换输入和连续点击控制按钮。

### 主责路径

frontend/src/features/visualization/、frontend/src/features/playback/。整体HTML和app入口通过02接入。

### 依赖与验收

依赖04完整steps和02输入重置。15日先演示mock，17日接真实执行。验收：从初始化到结果完整播放；指针、区间与变量一致；回看/重置正常；新run开始后没有旧计时器继续推进。

## 6. 成员 04：算法与后端接口

### 具体实现

1. 实现JS二分查找引擎，生成init/probe/边界更新/found/not-found等独立状态快照。
2. 提供等价C/C++展示代码及sourceVersion/lineId映射，与06核验讲解口径，与08核验每步结果。
3. POST /api/algorithms/binary-search/runs 创建任务；GET /api/runs/:runId 查完整任务；GET /api/runs/:runId/steps/:stepIndex 查实际步骤。
4. 校验输入，处理run不存在、步骤越界、空数组、单元素、重复值和未找到；请求大小、数组长度和保留时间统一写入契约。
5. 从06数据提供题目，展示题目时不提前返回答案；实现POST /api/exercises/check，用确定答案判分。
6. 保存run供05工具读取；将05独立Agent handler接入服务；模型失败不影响算法和判分。

### 主责路径

backend/src/algorithms/、backend/src/runs/、backend/src/routes/、backend/src/server.js、shared/algorithms/。

### 依赖与验收

依赖01契约、06题库，输出供02/03/05/07使用。15日引擎与映射，16日接口。验收：08人工预期全部核对；相同输入轨迹可复现；历史快照不被修改；接口错误明确；模型未配置时仍可完整执行。

## 7. 成员 05：Agent与聊天

### 具体实现

1. 后端读取配置并接入DeepSeek；配置缺失返回明确错误，不假装有模型输出。密钥不进入前端或提交记录。
2. 实现查询当前步骤工具：只读04服务端状态，取得runId/stepIndex对应变量与事件。
3. 实现知识检索工具：读取06核验的知识卡，按问题、主题和关键词返回内容与出处。
4. 组织问答流程：识别问题 → 取状态/知识 → 解释 → 标注step与资料引用。记录工具实际调用情况。
5. 支持观察提示、规则提示、完整解释三级辅导；不承担客观题权威评分。
6. 实现聊天输入、发送、加载、错误、重试和“针对第几步”的标签。提问后切换步骤，旧答案仍指向原步骤。
7. 记录真实usage、调用次数、耗时，结合账单管理30元测试上限；超时或失败时基础学习流程继续。

### 主责路径

backend/src/agent/、backend/src/knowledge/、frontend/src/features/agent/。公共入口由02/04整合。

### 依赖与验收

依赖04状态、06知识、团队实际模型账户。15日接口和聊天初稿，18日真实联调。验收：解释对应实际变量；引用可回到状态与知识卡；缺配置/超时处理有效；能够给08提供真实输出和用量记录。当前分工阶段不调用付费模型。

## 8. 成员 06：知识与题目

### 具体成果

4. 编写至少5道过程题：中点、下一步边界、未找到、单元素/空数组、重复值约定；给明确答案、解析、三级提示和出处。
5. 与04核对实现版本，与07核对题目展示，与08交叉检查答案；正式检索只使用verified=true内容。
6. 与09拆分正式知识覆盖表，区分教材内容与官方大纲对应，不能将仅有目录的单元标为完成。

### 主责路径

content/knowledge/、content/exercises/、content/sources/、content/coverage/。

### 日期与验收

15日首批内容，16日可联调数据。05能找到相关卡片；07能显示题目；08能独立核查出处与答案；没有整本教材扫描件、猜测页码或未验证参考答案。

## 9. 成员 07：练习记录与调研

6. 给09提供真实调研依据，给10提供可用于展示的匿名结论；公开材料不写虚构参与者。

### 路径、日期与验收

## 10. 成员 08：测试与效果验证

### 具体成果

1. 根据核验后的算法代码人工推演预期，不调用被测引擎生成自己的标准答案。
2. 最少覆盖普通命中、首尾命中、未找到、空数组、单元素、重复值；检查每步边界、中点、行标识和结束结果。
3. 操作检查：暂停、回看、重置、切换输入、刷新记录、缺模型配置、调用失败和超时。
4. 对三类问题做真实对比：正常步骤解释、边界解释、错误理解纠正。用同一模型、同一基本问题/输入，记录定制组额外工具与资料。
5. 保存模型标识、设置、提示、真实输出、状态/资料引用和耗时；按准确性、状态一致性、出处、提示有效性核验。
6. 如没有优势或出现失败，如实报告；三个案例用于证明代表性任务，不夸大为全领域统计提升。
7. 整理缺陷编号、复现步骤、负责成员、修复状态、复测证据；20日前交给01/10。

### 路径、日期与验收

tests/、docs/evaluation/。15日预期和清单，19日原始对比，20日报告。其他成员能按记录复现；静态检查不替代业务验收；没有用mock代替真实实验。

## 13. 并行开发的共同规则

- 02主维护frontend/index.html和app.js；03/05/07提供独立模块，让02装配。
